# 当前视野资源分工 V1

候选 `opponents/generalist-allocation-v1` 完整复制冻结 V5，仅增加 `allocation.hpp` 和导航接入；不含投资、协作、探索或食物密度势场。目标是减少可见队友同时追同一颗珠，而不是把分工结果计作收入。

## 已实现合同

- 资源只取当前可见、未被身体占据的真实珍珠，最多 12 颗；按自己的已验证图距离排序截取。参与者为自己和当前可见友军头，最多 8 个，自己始终保留。
- 每个参与者在自己的历史 Atlas 中搜索已知有向边和已解析门户，最多展开 2048 个节点、深度 32。所有要求的目标距离已找到就停止；未找到或截断不证明不可达。当前其他单位身体阻断；搜索对象自己的身体可被乐观穿过，故图路线只是导航估计，仍须原候选管线验证真实旧身体。
- 自己使用真实长度；友军仅使用当前可连续追溯的可见身体长度下界，至少为规则最短长度 2。预计到达时间为图距离除以该长度对应的免费额度并向上取整，不假定知道友军完整长度、付费计划、目标或未来行动。
- 按到达时间做有界贪心拍卖，每个头最多领一颗，每颗最多分给一个头。Queen 只有在预计到达时间不比最快参与者多一轮时才优先；随后按预计时间、距离、单位 ID、坐标稳定排序。
- 只有自己和至少一个队友都具有到同一真实珍珠的已找到路线时才启用分工。无可验证竞争时，原导航目标与场完全保留。启用后，自己分得的珠成为导航目标，队友已领珠不再吸引自己的食物导航；未分得目标时仍可选择原有记忆食物、刷新点或探索目标。
- 即时吃珠奖励、实际付费计算、完整身体碰撞、安全层级、分裂门槛和 `food_sites` 计数均保留。走到已被队友领走的珠仍会正常获得实际食物奖励，分工不强制绕路或禁止逃生。

编译期 `ALLOCATION_DISABLE` 跳过分工，保留 V5 导航，供固定消融使用。默认参赛启用，无运行时开关。

## 验证与冻结

官方 C++/WASM 检查通过：冲突分工、单人原目标、墙、未知/已解析门户、Queen 到达机会限制、友军长度下界、实际 `choose` 的食物与支付账；继承的身体/支付/门户记忆、出生头及短死端排序回归通过，关闭分工的导航回归通过。

官方协议检查 35 个场景、38 帧通过，峰值 11,143,695 CPU 点。另有 8 个合成历史 Atlas 预算检查：4096 个旧已知格、当前仍只有 49 格合法观察、8 个友头、12 个候选资源，覆盖 L3/L32、Queen/worker、环面和门户；每例包含一次额外显式建图及实际 `choose` 再次建图，峰值 22,436,423 CPU 点。这不是真实历史路线或生产全局最坏上界。未运行比赛。

## 局限与待验证

各单位视野、Atlas 和身体长度下界不同，会独立产生不一致分工；没有通信或执行承诺。贪心拍卖不保证最优匹配，也不保证珠最终被采到。友军真实长度可能更大，当前外部身体会移动，图距离不计身体释放和未来敌头封锁。截断、未知门户及旧图信息都单列指标，不当作完整可达性证书。是否减少追逐冲突、提高整场实际资源净收益，须用新外部配对比赛的实际执行账验证，不能从拍卖目标数推算食物或覆盖收益。
